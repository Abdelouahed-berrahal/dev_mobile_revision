Architecture des microprocesseurs mobiles

SoC, CPU, GPU, DSP, Modem, Sécurité — CISC vs RISC — ARM vs x86

Qu'est-ce qu'un SoC ?

Un SoC (System on a Chip) est un circuit intégré unique qui regroupe tous les composants essentiels d'un ordinateur sur une seule puce. C'est le "cerveau complet" d'un smartphone.

Analogie : Si un PC de bureau est une ville avec des bâtiments séparés (CPU dans un quartier, GPU dans un autre), le SoC est une ville miniaturisée sur un timbre-poste — tout est là, compact et optimisé.

CPU

Unité Centrale de Traitement. Exécute les instructions logiques et arithmétiques. Ex : Cortex-A78 dans Snapdragon 888.

GPU

Unité de traitement graphique. Gère l'affichage, les jeux, le rendu 3D. Ex : Adreno 660 (Qualcomm).

DSP

Digital Signal Processor. Traite les signaux audio, voix, capteurs sans mobiliser le CPU.

Modem

Gère les communications radio : 4G/5G, Wi-Fi, Bluetooth. Intégré ou externe selon le SoC.

Sécurité (TEE)

Enclave sécurisée : stocke les clés biométriques, mots de passe, données sensibles.

NPU / ISP

NPU : Neural Processing Unit pour l'IA. ISP : Image Signal Processor pour la photo.

ARM domine le marché mobile à plus de 95% car sa consommation énergétique réduite préserve l'autonomie de la batterie.

Architecture ARM : Big.LITTLE

Les SoC modernes combinent des cœurs Big (puissants, pour les tâches lourdes) et LITTLE (économes, pour les tâches légères).

Snapdragon 888 : 1× Cortex-X1 (performance max) + 3× Cortex-A78 (performance) + 4× Cortex-A55 (efficacité)

Cycle de vie d'une Activity

7 méthodes de rappel — de la création à la destruction

onCreate()
Initialisation : vues, données. Appelé une seule fois.
↓
onStart()
L'activité devient visible (pas encore interactive).
↓
onResume()
En avant-plan, interactif. L'utilisateur peut agir.
↓ ← L'utilisateur est ici

Partiellement masquée. Sauvegarder l'état.
↓

Complètement invisible. L'app tourne en fond.
↓

Détruite définitivement. Libérer ressources.
+ onRestart() : si l'activité revient depuis onStop

Exemple de code — onCreate

@Override
protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    setContentView(R.layout.activity_main);
    
    // Récupérer les vues
    Button btn = findViewById(R.id.monBouton);
    
    // Restaurer l'état si rotation/interruption
    if (savedInstanceState != null) {
        String val = savedInstanceState.getString("cle");
    }
}

Sauvegarde d'état

@Override
protected void onSaveInstanceState(Bundle outState) {
    super.onSaveInstanceState(outState);
    outState.putString("cle", maVariable);
    // Appelé AVANT onStop — préserve l'état lors des rotations
}

Communication

Intents et Intent Filters

Mécanisme de communication entre composants Android

Un Intent est un message asynchrone permettant à un composant de demander une action à un autre composant — au sein de la même app ou d'une app différente. C'est le bus de communication d'Android.

CritèreIntent ExpliciteIntent Implicite
CibleComposant précis (classe nommée)Action déclarée (n'importe quel composant)
UsageNavigation interne à l'appDéléguer à une autre app
ExempleOuvrir MainActivity depuis LoginActivityPartager du texte, ouvrir une URL
RésolutionDirecteVia Intent Filters dans les Manifests

Code — Intent Explicite

// Naviguer vers une autre activité
Intent intent = new Intent(this, DetailsActivity.class);
intent.putExtra("id_produit", 42);
intent.putExtra("nom", "Laptop");
startActivity(intent);

// Dans DetailsActivity.java :
int id = getIntent().getIntExtra("id_produit", 0);
String nom = getIntent().getStringExtra("nom");

Code — Intent Implicite

// Ouvrir un site web
Intent intent = new Intent(Intent.ACTION_VIEW);
intent.setData(Uri.parse("https://www.google.com"));
startActivity(intent);

// Partager du texte
Intent shareIntent = new Intent(Intent.ACTION_SEND);
shareIntent.setType("text/plain");
shareIntent.putExtra(Intent.EXTRA_TEXT, "Mon texte");
startActivity(Intent.createChooser(shareIntent, "Partager via"));

Intent Filter dans le Manifest

<activity android:name=".MainActivity">
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
</activity>

Actions communes

  • ACTION_VIEW — Afficher des données (URL, carte, vidéo)
  • ACTION_SEND — Partager du contenu
  • ACTION_DIAL — Ouvrir le clavier téléphonique
  • ACTION_CALL — Appel direct (nécessite permission)
  • ACTION_PICK — Sélectionner depuis une source
  • ACTION_MAIN — Point d'entrée de l'application

SQLite dans Android

Base de données relationnelle embarquée — stockage local persistant

SQLite est une base de données SQL légère, sans serveur, intégrée directement dans Android. Chaque application possède sa propre base, stockée dans /data/data/<package>/databases/.

Types de données SQLite

Type SQLiteÉquivalent JavaDescription
INTEGERint, longNombres entiers
REALfloat, doubleNombres décimaux
TEXTStringChaînes de caractères
BLOBbyte[]Données binaires
NULLnullValeur nulle

SQLiteOpenHelper — Classe essentielle

public class MaBaseDeDonnees extends SQLiteOpenHelper {
    
    private static final String NOM_BDD = "maBase.db";
    private static final int VERSION = 1;
    
    public MaBaseDeDonnees(Context context) {
        super(context, NOM_BDD, null, VERSION);
    }
    
    @Override
    public void onCreate(SQLiteDatabase db) {
        db.execSQL("CREATE TABLE utilisateurs (" +
            "id INTEGER PRIMARY KEY AUTOINCREMENT, " +
            "nom TEXT NOT NULL, " +
            "email TEXT UNIQUE, " +
            "age INTEGER)");
    }
    
    @Override
    public void onUpgrade(SQLiteDatabase db, int oldV, int newV) {
        db.execSQL("DROP TABLE IF EXISTS utilisateurs");
        onCreate(db);
    }
}

CISC vs RISC — Le Chef étoilé vs le Fast-food

CISC = Chef étoilé : peu de plats, mais très élaborés, longs à préparer. Puissant mais gourmand.

RISC = Fast-food : beaucoup de plats simples, préparés ultra-rapidement. Efficace et économique. Parfait pour le mobile !

Les 4 composants Android — "ASCB"

Acronyme

Activity • Service • Content Provider • Broadcast Receiver

"All Smart Coders Build" — tous les bons développeurs construisent avec ces 4 blocs.

Intent Explicite vs Implicite — Le courrier

Explicite = Lettre nominative : vous écrivez le nom exact du destinataire. "Envoyer à M. Dupont, bureau 301." → Adresse précise.

Implicite = Petite annonce : "Quelqu'un sait-il imprimer ?" → N'importe qui qui peut le faire répondra.

REST vs SOAP — Le SMS vs le Fax

REST = SMS : court, rapide, efficace, format libre. Tout le monde l'utilise aujourd'hui.

SOAP = Fax : formel, enveloppe obligatoire, papier à en-tête, lourd — mais encore utilisé dans les grandes entreprises.

Dalvik vs ART — Le Cuisinier vs le Traiteur

Dalvik (JIT) = Cuisinier à la commande : lent au premier plat (compilation à l'exécution), mais flexible.

ART (AOT) = Traiteur qui prépare tout à l'avance : installation plus lente, mais service ultra-rapide ensuite.
